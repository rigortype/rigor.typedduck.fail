ステータス: **Accepted、2026-08-26**。`rigor effects`と4つのスナップショットの動詞について、このADRのスライスが吸収した#482のエントリー分割の上に実装済み（`Analysis::EffectsCacheProbe`）。2026-08-25の機能ウォーム/コールドキャンペーン（[`docs/notes/20260825-feature-warm-cold-corpus-perf.md`](../../notes/20260825-feature-warm-cold-corpus-perf/)）に基づく。

## コンテキスト

2026-08-25のキャンペーンがエフェクトテーブルのサイドカー（#475）、合成スキャンの短絡（#477）、そしてエンベロープ位置の遅延化（#479）を着地させたあと、ウォームな`rigor effects` / `rigor effects check`はほとんど何の作業もしていない——それでいてウォームな`rigor check`の2〜2.5倍かかる。mastodonでの計測では、checkの0.37秒に対して0.74秒であり、そのうち実行中の作業は0.35秒で、残りはプロセスのブートだ——推論エンジンと環境層の`require`であり、2つのキャッシュキーを計算して2つのキャッシュ値を採用するためだけにロードされている。`rigor check`はすでにこれを払うことを拒んでいる: ADR-87のWD4の`RunCacheProbe`は、`rigor/inference`を`$LOADED_FEATURES`へ入れることなくウォームなcheckを提供する。エフェクトのサーフェスには等価物がないので、あらゆるエフェクトのCIゲートが、Marshalのblobを読むために実行ごとのエンジンのブートを払っている。

実現可能性は、仮定ではなく現行のコードに対して検証した:

- 診断キーの半分はすでにエンジン不要である——`RunCacheProbe`が今日それを計算している（`lib/rigor/analysis/run_cache_key.rb`）。
- その上に載るエフェクトの同一性（`lib/rigor/effects/identity.rb`）は、語彙バージョン、カタログファイル、`effects:`ブロック、そして`PluginFacts#digest`をダイジェストする——そして`compute_digest`（`lib/rigor/effects/plugin_facts.rb:325`）は、ロードされたプラグインが宣言した寄与の純粋関数である。それが必要とするのは`Plugin::Loader`だけで、エンジンもプロジェクトの発見も決して必要としない。
- レポートは伝播されたテーブルとユニットごとのソースを必要とする;どちらも#475のサイドカーの中にある（`[collections, table]`——ソースはコレクションのサマリーキーから導出される）。祖先関係に依存する宣言レーンのリンク付け（#464/#467）は収集時に起こり、キャッシュされたサマリーへ焼き込まれるので、提供された実行がそれを失うことはありえない。
- `effects check` / `diff`はさらにレジストリ（プラグインのロード）、リーチのglob（設定）、そしてコミットされたスナップショット（YAMLの読み取り）を必要とする。`Snapshot.build`は0.006秒と計測された。

## 決定

checkのプローブと並ぶエフェクトのプローブ: `rigor effects`と4つのスナップショットの動詞は、まず実行全体のエフェクトのサマリーのエントリーから提供することを試み、設定・キャッシュ・プラグインローダー・`effects/*`の値層をロードする——`rigor/inference`はロードせず、`Environment`もロードしない。ミスした場合、および保存された値では答えられないモードの場合は、変更のないフルのRunnerのパスへ辞退する。

判定基準は、#442/#428の規則を一般化したものである: **プローブがサーフェスを提供してMAYよいのは、そのサーフェスが与えうるすべての答えが、保存された値と宣言だけから再現可能であるときに限る;生きた解析状態から計算される答えは、キャッシュエントリーに相乗りするか、さもなければ辞退を強制しなければならない**。 #428のファミリーは、この規則の2つの半分が別々に決められたときに何が起こるかを記録した;新しいプローブのサーフェスは、それを学び直す教訓としてではなく、設計上の前提条件として採用する。

実装されたとおりの作業上の決定:

- **WD1**——辞退リストは、キーが再現できないか、エントリーが答えられない理由のすべてである: キャッシュのルートがない、`effects.check?`がオフ、プローブが再構築できないキー（プラグインが仮想RBSを合成するプロジェクト。ADR-87のプローブが同じ理由ですでに辞退しているものだ）、ミス、古い依存関係、破損したエントリー、誤った形の保存値。パス引数は辞退では*ない*——それはランナーのパスでそうであるのとまったく同じように解析対象の集合へ加わり、それに応じてエントリーをキー付けするので、カバーされていないスコープは通常のミスとして辞退する。
- **WD2**——ADR-87の形での、空虚でない提供のスペックを、サブプロセスで行う。提供された側の腕は、約90件をロードする解析側のコントロールに対して、`$LOADED_FEATURES`内の`analysis/runner` / `environment` / `scope`のエントリーが**ゼロ**であることをアサートする;`inference/`ディレクトリの件数はゼロではなく1桁の低下としてアサートする。`Effects::Catalog`と`Reflection`が、そもそもラベルを名指しうるあらゆるパスで、そのディレクトリから値層のファイルをいくつか引っ張るからだ。すべての辞退の例は「それでも答えなければならない」例と対にされ、ドリフトのゲートが依然として1で終了することを証明している。
- **WD3**——スナップショットの構築は、その入力をどちらのレーンが生んだかによらず1つである（`#snapshot_from`）。そしてプローブは、呼び出し元に語彙を再構築させるのではなく、キーのためにすでに構築した語彙を返すので、提供された答えと解析された答えがドリフトすることはありえない。
- **WD4**（[#482](https://github.com/rigortype/rigor/issues/482)から吸収）——実行全体のエフェクトのキャッシュは、1つのキーと1つの依存関係ディスクリプタの下で2つのエントリーを使う: ウォームな実行が提供元とするサマリーと、インクリメンタルな再チェックおよびフェイルソフトな再伝播だけが読むコレクションである。コレクションはローダーの背後で到達可能なままなので、この分割が予期していなかった消費者は、空のテーブルを読むのではなくそれをロードする。

## 却下／先送りした選択肢

- **デーモン／ウォッチモード**——すべてのコマンドについてブートのコストを平坦化する。計測された形を記録したうえで、すでにプロダクトの決定として先送りされている（2026-07-13のキャンペーンの§④）。このADRのプローブは、それを必要とすると計測された2つのサーフェスに対するCLI優先の答えである。
- **フルのパスのrequireを絞る**——エンジンの`require`*こそ*が大部分である;キーを計算するが解析はしない、というような`rigor/inference`の有用な部分集合は存在しない。
- **何もしない**——あらゆるエフェクトのゲートをcheckのウォームの床の2〜2.5倍のままに残す。その出費が遊んでいるブートであるときに、それは「エフェクトは高価だ」と読まれてしまう。

## 帰結

- ウォームな`rigor effects`はredmine / mastodonで**−34% / −38%**、`rigor effects check`は**−26% / −38%**（インターリーブしたA/B、3反復、中央値は0.76 → 0.50秒と0.93 → 0.58秒;提供側の腕はどの反復も解析側のどの反復にも勝った）。出力は両プロジェクトで、既定のレポート・`--full --why`・`--format json`・`explain`のすべてにわたってバイト同一である——mastodonでは175,534行のJSON。
- エフェクトのサーフェスが増えていく中で、2つ目のプローブのサーフェスは答えについて完全であり続けなければならない。上記の判定基準がそのガードであり、WD2の`$LOADED_FEATURES`のスペックが、黙った乖離を沈黙のレーンではなくレッドのスペックにする。**再評価のトリガー:**生きた解析状態から計算される新しいエフェクトの答えは、出荷される前にサマリーのエントリーのフィールドか辞退のどちらかを追加しなければならない。
- プラグインのロードは提供されるパスに残る（語彙はそこから来るし、キーもそうだ）——0.02〜0.04秒と計測されており、最適化の余地ではなく正しさのために必要なものだ。
- **サマリーのエントリーは規模において小さくはなく、#482のその見積もりは間違っていた**。gitlabの`app lib`では、コレクションの4.8MBに対して5.1MBある: テーブルが行ごとに`causes`と`edges`を運んでおり、それこそが`explain`と`--why`を提供可能にしているものだ。それらを落とせば読み取りは半減するが、ウォームな実行で両方のサーフェスが黙って壊れる——まさに判定基準が禁じることだ——ので、この分割のモノレポ規模での勝ちは「ほとんど何もロードしない」ではなく「2つではなく1つのblobをロードする」である。計測し、記録し、追わない。
