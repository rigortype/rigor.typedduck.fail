Status: **Accepted — WD1（祖先／ファイルレベル依存者のための宣言シェイプゲート）＋WD2（シンボル依存者のための観測キー戻り値サマリーゲート）実装済み（[PR #90](https://github.com/rigortype/rigor/pull/90)）**。 PR #88のB1コメントのみゲートを**本体**編集へ拡張する：依存者が再解析されるのは、それが消費できる何かが実際に変わったときだけである。ADR-88の上でのみ健全である── プラグインファクトの値フィンガープリントこそが、「プラグインから見えるサーフェスは不変」を検査可能な前提にするものである。

根拠：[`20260714-edit-shape-recon.md`](../../notes/20260714-edit-shape-recon/)（クロージャの形状。S5aのクラスメソッド編集 → 341ファイルの祖先クロージャ。あらゆるコメント形状にわたり`diags_changed = 0`）＋[ADR-88](../88-incremental-plugin-fact-soundness/)。

## Context

#87／#88／ADR-88のあと：コメントのみの編集は潰れる（B1コードフィンガープリント）。シンボルエッジ依存者は、変更されたメソッドごとのソースフィンガープリントでのみ再チェックする。プラグインファクトは値によってスナップショットを無効化する。残る過剰伝播は**本体**編集である：

- **(a)**任意の本体編集がすべての祖先／ファイルレベル依存者を再解析する。偵察のS5a── 13呼び出し側の`def self.safe_find_or_create_by`本体編集 ──は341ファイルを再解析した。それらはクラスの*宣言シェイプ*だけを消費しており、本体編集はそれを変えない。
- **(b)**推論される戻り値型が、以前に観測されたすべてのコール形状で不変な本体編集でも、なおそのすべての呼び出し側を再解析する。

## Decision (criterion)

編集されたファイルFの依存者Dが再解析されるのは、（DがFから消費できるもの）×（実際に変わったもの）の交わりが空でないときに限る。ここで「何が変わったか」は**永続化された**サマリーを比較することで証明され、各サマリーは完全な消費可能サーフェスを覆う：

1. **宣言サーフェス**（祖先／ファイルレベルのコンシューマー）：ADR-85のシードバンドルで、defごとの**コード**フィンガープリントをdefごとの**シグネチャ**シェイプに置き換えたもの── 名前、種別（インスタンス／シングルトン）、完全なパラメータ構造（種別／名前／デフォルトの有無）、可視性、祖先（スーパークラス／include）、メンバーレイアウト、メソッドの存在、**そしてdefの開始行**である。本体編集はそれを等しいままにし、アリティ／可視性／メソッドの追加削除／祖先の編集はそうしない。
2. **振る舞いサーフェス**（シンボルコンシューマー）：defごとの観測キー戻り値サマリー── ADR-84メモのFのdefに対する`(receiver-descriptor, arg-descriptors) → return-descriptor`エントリーをスナップショットに永続化したもの ──に、**加えて**エフェクトチャネル（ADR-56／`af3efef3`の内容変更パラメータ集合。呼び出し側が引数のフロアリングのために消費する、defごとの静的プロパティ）である。

**両方**の前提：ADR-88のプラグインファクトフィンガープリントが一致したこと（さもなければ既にフル再解析）。スキップは記録と合成する── スキップされた依存者のエッジ／キャッシュはスナップショット内で不変のまま引き継がれる。

## Working decisions

### WD1 — 宣言シェイプゲート

再チェックで、変更された各ファイルについてその{ScopeIndexer.declaration_signature}（上記の宣言サーフェスにわたるSHA-256。単一ファイルのライブインデックスから読まれ、パラメータ構造はdefノードから直接── 意図的に構文的であって型付きではない）を計算する。それがスナップショットの格納済みシグネチャ（キャッシュ時に同じライブインデックスから、シードバンドル上で構築される。`IncrementalSnapshot::SCHEMA`を9→10）と等しければ、そのファイルは宣言**安定（STABLE）**であり、`unstable`集合から外れる── その祖先／ファイルレベル依存者はスキップされる（シンボル依存者はフィンガープリント／WD2に統べられたまま）。これはB1を**一般化する**：コード安定 ⟹ 宣言安定なので、ゲートはB1のコメント除去済みコードフィンガープリントから宣言シグネチャ（B1のスキップ集合の上位集合。なお健全）へ切り替え、B1のコメント取り込みプラグイン用オフスイッチを保つ。

クロージャ機構は既にこれを正しくルーティングしていた：`affected_with_symbols(unstable, changed_pairs, …)`は、ファイルが`unstable`に入っているときにのみ宣言安定ファイルの祖先依存者を加えるので、そこから取り除くことが変更のすべてである。その変更されたシンボルペアはなおそのシンボル依存者を寄与する。

**defサイトの行シフト — ドラフトからの乖離（健全性駆動）**。ドラフトは、行シフトしたdefは（ADR-88 WD3の`user_def_site_for`エッジ経由で）そのサイト消費依存者だけを再チェックし、他はスキップすることを提案した。実現されたシグネチャは代わりに**各defの開始行を含む**ので、行シフトする本体編集はシグネチャを動かす → ファイルは宣言**不安定（UNSTABLE）**になる → その祖先／ファイルレベル依存者（`project_definition_site`を埋め込む`call.undefined-method`コンシューマーを含む）がすべて再チェックされる。これは健全性に必要である：ADR-88 WD3のシンボルフィンガープリントは行不変（line-INVARIANT。defのソーススライステキストは不変）なので、シフトしただけで他は不変のdefをフラグせず、ファイルレベルのエッジだけがADR-17のサイトコンシューマーを覆う── B1が行シフトで持つのと同じ保守的挙動である。だから行シフト編集は完全な依存者集合を保つ（健全、粗い）。潰れるのは**同一行**の本体編集だけである（ローカルなリネーム、内部リテラル）。より細かいサイトごとの精密さは延期する。`--verify-incremental`の行シフトspec（ADR-88 WD3）は**この**ゲートを通しても緑のままであり、WD4の行シフトケースはサイトコンシューマーが再チェックされることを主張する。

### WD2 — 観測キー戻り値サマリーゲート

ファイルごとの観測キーを、境界を定めて永続化する：defあたり`RETURN_SUMMARY_KEYS_PER_DEF`（8）キー、`RETURN_SUMMARY_TOTAL_CAP`（4000）def、`describe(:short)`の戻り値記述子＋エフェクト集合。それらは各ランのあとにADR-84の戻り値メモから収穫される── `MemoEntry`はコール記述子（`receiver`＋`arg_types`）を得たので、サマリーは実際に観測されたキー型を持ち運ぶ（`ExpressionTyper.harvest_return_memo`＋`Runner#return_summaries`。各メモエントリーをディスカバリインデックスを通してその`(path, "Class#method"|"Class.method")`にマップする）。Marshal不能なキーはスナップショット保存時に落とされるので、キャッシュ書き込みが失敗することは決してない。

再チェックで、不変のシグネチャシェイプでなお存在し永続化サマリーを持つ各変更defについて、セッションはその戻り値を各旧キーで再評価する（`Scope#user_method_return` → ADR-84メモ、最終値のみ）。これはセッション側のランナープローブ（`Runner#evaluate_return_types`── シードバンドルからディスカバリー＋環境を一度だけ構築、ファイル解析なし）を通して行われる。すべての戻り値が等しく**かつ**エフェクト集合が等しい → そのdefのシンボル依存者を落とす。いずれかの不一致、defの欠落、シグネチャの変更、キャップ超過、またはメモが再評価を拒むキー（一時的なADR-84結果）→ 依存者を保つ（保守的）。プローブは宣言安定な変更ペアがサマリーを持つときにのみ走るので、コメント編集（変更ペアなし）はWD2コストをゼロしか支払わない── ウォールゲートの性質である。

**適格性の制限 — ドラフトからの乖離（健全性の完全性）**。シンボル依存者は、呼び出される側の本体からその戻り値と内容変更エフェクトより**多く**を消費する：ivarの確定代入（呼び出される側が代入するフィールドを、同じクラスの呼び出し側が読む。ADR-58 WD3。呼び出される側自身の呼び出しを通して推移的に）と、`yield`値（ブロックを渡す呼び出し側）である。戻り値＋内容変更サーフェスだけを比較することは、それらに触れるdefにとって**非健全**となる。だから戻り値ドロップは`gate_eligible_def?`でゲートされる：defがインスタンス／クラス変数を書かず、`yield`せず、暗黙self呼び出し（推移的な共有状態書き込みを持ち運びうる）をしないこと── 純粋に構文的で保守的な十分条件であり、その下では戻り値＋内容変更が完全なクロスファイル本体サーフェスと**なる**。不適格なdefはその依存者を保つ。一般的な全サーフェスゲート（推移的ivar代入サマリー＋yield型サマリー。制限を持ち上げる）は延期する。

### WD3 — プラグインファクトの前提

ゲートが適用されるのは、スナップショットのプラグインファクトフィンガープリントがこのランで一致したときだけである。ADR-88が整った状態で、これは構造的に強制され、仮定ではなく主張される：`IncrementalSession#run_incremental`は、`if reuse`ブランチの**内側**（`@plugin_fact_reusable.reusable_against?`）でのみゲートされた再チェックの結果を信頼し、ファクト不一致**または**不透明な寄与プラグインは再チェックを捨ててフルベースラインを走らせる── だからクロスファイル寄与がファイルの**本体**の、フィンガープリント化されたサーフェスを超えた部分から導かれるプラグインは、WD1／WD2のスキップを成立させることが決してできない。B1のコメント取り込みプラグイン用オフスイッチは、シグネチャ（コメントを無視する）がさもなければ誤スキップしてしまう唯一のコメント読み込みプラグインのために保持される。

### WD4 — 検証バッテリー

作り込んだspec（`incremental_session_spec.rb`）で、それぞれゲートなしで赤／ありで緑となり、すべてフルとバイト一致であることを主張する：

- **WD1** — 同一行の本体編集 → 祖先依存者がスキップされる（`341 → そのシンボル呼び出し側`）。アリティ変更 → 伝播。可視性変更 → 伝播。メソッド追加 → 伝播（負のエッジ）。戻り値可視の本体編集（`Constant`の畳み込み）→ シンボルフィンガープリント経由で伝播。
- **WD2** — 戻り値保存リファクタ（観測キーで同じ戻り値）→ シンボル依存者がスキップされ＋マージされた診断がバイト一致。戻り値可視の編集 → 伝播。変更エフェクトの変化（呼び出される側が引数を変更し始める）→ 伝播。不適格なdef（ivar書き込み）→ その依存者を保つ。
- **WD3** — ADR-88の行シフトspecがゲートを通しても緑のまま。

## Rejected / deferred

- **診断不変でのゲート** — 循環的（知るには依存者を解析する必要がある）。
- **エフェクトチャネル**なしの**推論サマリー同値でのゲート** — 引数のフロアリングは呼び出し側から見える。
- **ADR-88なしの前提なきゲート** — B1監査の内容読み込みプラグインの反論。
- **サイトごとの行シフト精密さ**（ドラフトWD1）— シンボルフィンガープリントは行不変なので、ファイルレベルのエッジだけがADR-17のサイトコンシューマーを覆う。したがってdefの行は宣言シグネチャ**の中**に住み、行シフトは完全な依存者集合を保つ（健全、粗い）。延期。
- **一般的な全サーフェスWD2戻り値ドロップ** — 推移的ivar代入＋yieldサーフェスを比較すれば適格性の制限が持ち上がる。各追加サーフェスの比較が健全だと証明することの後ろに延期。再評価トリガー：実コーパスで戻り値ドロップ対象のivar代入／yieldする呼び出される側への需要が実証されたとき。
- **ADR-88の無効化のWD5式コンシューマーごとの狭め化** — 延期のまま（ADR-88 WD5）。

## Consequences

S5a形の編集は潰れる（gitlabの`def self.safe_find_or_create_by`戻り値保存編集：**341 → 1**。WD1が340の祖先依存者すべてを落とす。`label.rb reference_prefix`のリテラル変更：**19 → 1**）ので、「自分の編集は型を変えるか？」という問いが伝播境界となる。適格なリーフの呼び出される側の戻り値保存リファクタは、その呼び出し側の再チェックをやめる（WD2）。ネガティブ：スナップショットはサマリーの分だけ増える（境界の定まった文字列／stat記述子）。完全に保つべき2つの新しい比較器サーフェス（WD4バッテリー＋`--verify-incremental`が保険）。観測キー再評価は変更ファイルごとに境界の定まった作業を加える── 宣言安定なペアがサマリーを持つときだけ。全体を通して精密性を加える（precision-additive）── 型／診断／重大度の変更なし。コールド診断は`origin/master`とバイト一致（mail 26、kramdown 68）。gitlabの`--verify-incremental`はバイト一致（887/1,774、2,494、不一致0）。

**計測に関する注記（ゲートの期待数値からの乖離）**。 gitlabのS5aクロージャは、偵察が見積もった〜13〜14ではなく**1**に潰れた。`safe_find_or_create_by`は記録されたスコープ内シンボル呼び出し側が**ゼロ**だから（app/models＋app/controllers）── 偵察の「13呼び出し側」はテキスト的なものであって、記録された`symbol_dependents`ではなかった。だからWD1が計測されたgitlabの見出しである（340の祖先依存者を落とす）。WD2の戻り値ドロップはこの特定のgitlabメソッドでは発火しない（`safe_find_or_create_by`は不適格── `find_by`／`transaction`を自己呼び出しする。`Label.reference_prefix`はクロスファイルのシンボル呼び出し側を持たない）。その機構は代わりにWD4の作り込みバッテリーで証明される。
