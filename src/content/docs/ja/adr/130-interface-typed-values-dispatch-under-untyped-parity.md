ステータス: **Accepted、2026-11-04、メンテナーにより批准**。実装済み: スライス1aは#2808、スライス1bは#2815、スライス2（#2686）は#2822でそれぞれマージされた。

本ADRは#929の値側の半分の一部、すなわち`Rigor::Plugin`配下のプラグイン向けインターフェースで型付けされた値のみを扱う。以下の3つはそれぞれ再突入条件付きで延期する。

- すべてのRBSインターフェースに対する同一のファセット。
- 構造的代入可能性。
- ロールテーブル。

プロトタイプは`lib`、48個のプラグインおよびサンプルツリー、ならびに14個の調査ターゲットで計測した。

- いずれのターゲットでも診断行を一切追加しなかった。
- 振る舞いのパリティ差分は空であった。
- ディスパッチをオフにした状態で、`lib`およびプラグインツリーに対するsig-genの出力はmasterとバイト単位で一致した。
- ディスパッチをオンにした状態のlensは15箇所のプラグインツリーの戻り値サイトを変更し、これは意図した精度向上である。
- `lib`でのアロケーション増加は0.085%であった（第3ラウンドのHEAD時点）。

3回のレビューラウンドで以前のドラフトに対する指摘事項が再現された。すなわち11件の偽陽性と、ネストしたタプルおよびハッシュ形状のジョインという2件の構造的乖離である。すべてフィクスチャ化されている。本ドラフトでは偽陽性は解消され、ジョインはmasterと一致する。

根拠: [`docs/notes/20261104-interface-types-prototype-measurement.md`](../../notes/20261104-interface-types-prototype-measurement/)（3つのドラフトすべてのターゲットごとの差分、パリティ差分、sig-genおよびlensの出力、フィクスチャ、アロケーションの内訳）。

## コンテキスト

現在、RBSのインターフェース型は`untyped`に消去される。`RbsTypeTranslator::TRANSLATORS`は`RBS::Types::Interface`を`:translate_untyped`にマップしている（`lib/rigor/inference/rbs_type_translator.rb` ~L81）。このためADR-128のプラグインインターフェースが機能しない。

- `base.rbs`は各フックのスコープを`Rigor::Plugin::_Scope`として型付けしており、#2681がそれらの型をプラグインコードに運ぶ。
- `scope.type_of(node)`は依然として`Dynamic[top]`になる。
- そのため#2686の`plugin.api-surface`ルールが読み取る対象を持たない。

自明な修正は、インターフェース値を`Dynamic[_Foo]`として保持し、ディスパッチにそのファセットを読ませることである。しかし2回のレビューラウンドにより、エンジンが`Dynamic[top]`そのものをキーとして振る舞いを分岐しているため、この方法は安全でないことが判明した。以下の各障害が再現された。

- **`untyped`をキーとするサイト**。 `lib/`内の20箇所で`Dynamic`のファセットが`Type::Top`であるかを検査するか、型を`Combinator.untyped`と比較している。インターフェースファセットはこれらすべてから漏れ落ち、その結果7件の偽陽性が発生した。該当箇所には、オーバーロード選択の不精密パス、#1840の再合流、ADR-67 WD3のオーバーライド、ADR-84のメモ化免除などが含まれる。詳細はノートに一覧化されている。
  - 例: `x : _ToInt`のとき`(1 + x).nan?`が未定義の`nan?`を報告する。
- **ユニオンの正規化**。 `Dynamic[top] | Dynamic[top]`は1つのメンバーに重複排除されるが、`Dynamic[_A] | Dynamic[_B]`は`Dynamic`検査に引っかからない2メンバーのユニオンのまま残るため、2つのインターフェース値のジョインの後に`possible-nil-receiver`が続く。
- **呼び出しを受け付けないオーバーロードを持つメンバー**。 `xs : _Each[Integer, Array[Integer]]`に対する`xs.each.with_index`では、ブロックなしの呼び出しがブロック付きオーバーロードの戻り値を採用し、未定義の`with_index`を報告した。
- **エイリアスのメモ化**。一部のインターフェースだけを消去し他を消去しないようにしたことで、閉じたエイリアスのメモが変換順序に依存するようになった。
- **sig-gen**。インターフェース経由のディスパッチがsig-genの出力を変更した。
- **ネストしたジョイン**（第3ラウンド）。トップレベルのマージにより、masterでは1つになる`[Dynamic[_A]] | [Dynamic[top]]`が2つのアームとして残った。また`{ k: Dynamic[_A] } | { k: Dynamic[top] }`も2つの形状として残り、後続の`merge`がそれを`Hash`に潰した。
- **nilになり得るブロック渡し**（第3ラウンド）。`xs.each(&blk).with_index`がブロック付きオーバーロードを採用し、未定義の`with_index`を報告した。

用語（[`CONTEXT.md`](https://github.com/rigortype/rigor/blob/master/CONTEXT.md)）: *インターフェース*はRBSの構造型を指し、*プロトコル*はADR-28のものを指す。

## 決定

`Rigor::Plugin`配下のインターフェースで型付けされた値は、エンジン内のあらゆるサイトに対して`untyped`として扱う。ただし1つの例外がある。そのインターフェースが宣言するメンバーに対する呼び出しであり、かつメンバーのオーバーロードの1つがその呼び出し形状を受け付ける場合、そのメンバーのRBSを通じて解決する。それ以外のすべてのRBSインターフェースは現在どおり`untyped`に消去する。

**基準（振る舞いのパリティ）**。インターフェースディスパッチをオフにした状態で、`rigor check --format json`はすべてのコーパスにおいて消去時とバイト単位で一致しなければならない。

- 唯一の例外は描画される型テキストである。すなわち`dump_type`、ホバー、`type-of`、および値の型を出力する診断メッセージである。
- ファセットが変更してよい振る舞いはディスパッチのみである。
- スペックが両モードでパリティフィクスチャを実行し、この基準を強制する。ノートにはコーパス全体に対する同じ差分が記録されている。

## 運用上の決定（Working decisions）

**WD1 — 表現**。プラグインインターフェース値は`Dynamic[Type::Interface(name, type_args)]`とする。

- `Type::Interface`は`Dynamic`ファセットとしてのみ現れるプレーンラティスキャリアである。`name`には`Nominal`のスペリングを用いる。
- **ジェネリクス**。型引数は呼び出し元のコンテキストで変換する。ディスパッチは`RbsLoader#interface_definition(name).type_params`からインターフェース自身のパラメータを束縛する。未束縛のまま残ったデフォルト付きパラメータは`Dynamic[top]`となる。
- **`self`、`instance`、および`class`**。メンバー内部では、`self`はレシーバーとなる。`instance`および`class`は`Dynamic[top]`となる。
- **ユニオン**。 `Combinator.union`はファセット消去を法としてメンバーを重複排除する。
  - *ファセット消去*は`Dynamic[<plugin interface>]`を`Dynamic[top]`に書き換える。これは型を保持するあらゆるキャリア（`Dynamic`ファセットを含む）の内部に再帰的に適用される。
  - メンバー吸収も消去後の形式を比較するため、masterが吸収するアームをファセットが残すことはない。
  - 消去後に等しくなる2つ以上のメンバーは、その消去後の形式にマージされる。したがって`Dynamic[_A] | Dynamic[top]`は`Dynamic[top]`になり、`[Dynamic[_A]] | [Dynamic[top]]`は`[Dynamic[top]]`になり、`{ k: Dynamic[_A] } | { k: Dynamic[top] }`は`{ k: Dynamic[top] }`になる。これにより、ジョインはmasterの重複排除が与えるのと同じ形状を持つ。
  - ファセットはそこで失われる。ファセットは最後の手段であり、型ではない。
  - 1つのインターフェースメンバーと他のメンバーからなるユニオンは、そのメンバー上のファセットを保持する。
  - `Dynamic[_Scope] | Rigor::Scope`では、`untyped`をキーとするすべてのコンシューマーが述語を通じてそのインターフェースメンバーを見るため、masterが`Dynamic[top] | Rigor::Scope`を見るのと完全に同じになる。
  - そのユニオンに対するディスパッチはメンバーごとに解決する。両方のアームで宣言されている呼び出しは、masterが`Dynamic[top]`を返すのに対し、2つの答えのジョインを返す。
- **インターセクション**。 #529の「最初の情報を持つメンバー（first-informative-member）」ルールは変更しない。

**WD2 — パリティ: 1つの述語と2つのゲート**。

`Type::Combinator.untyped?(type)`は`Dynamic[top]`および`Dynamic[Interface]`に対して真を返す。`untyped`に基づいて寛容さを判定するすべてのサイトがこれを呼び出す。機械的には、`lib/`内の以下のいずれかを行うすべての式が対象となる。

- `Dynamic`の`static_facet`が`Type::Top`であるかを検査する。
- 型を`Combinator.untyped`と`==`または`equal?`で比較する。

`Combinator.dynamic`自身のコンストラクタ検査を除き、これらすべてをこの述語に移行する。ユニオンマージ（WD1）も同じ消去を用いる。

一部のサイトはファセットの内容そのものを読む。`ReceiverBlindBlock`、`BlockAutoSplat#opaque_array_carrier?`、`MatchRebinding`のRegexp検査、エフェクトコレクタ、およびセンサスのワイドニングである。これらはいずれも`Interface`用の分岐を持たないため、`Interface`ファセットに対してはそれぞれ`top`に対して返すのと同じ答えを返す。`receiver_descriptor`もファセットを読むが、これはディスパッチの例外である（WD3）。

ファセットの方がより精密になる箇所であっても、パリティは現在の振る舞いを維持する。

- ADR-67 WD3はインターフェースパラメータをオーバーライドする。
- RBSの`-> _Foo`という戻り値は、`untyped`の戻り値が特別扱いされるすべての箇所で`untyped`として扱われる。

2つのゲートがパリティを強制する。

- **振る舞いゲート**。スペックがすべてのパリティフィクスチャを2回実行する。
  - ディスパッチをオフにした状態では、単一の正規化——描画された各ファセット名`Dynamic[<plugin interface>]`を`Dynamic[top]`に置換する——を行った後、消去ベースラインと一致しなければならない。
  - それ以外のすべてはバイト単位で一致しなければならず、構造的乖離（余分なユニオンアーム、失われた形状）が描画テキストとして通過することはない。
  - ディスパッチをオンにした状態では、宣言されたメンバーの呼び出し箇所でのみ差分が生じ得る。
- **リントゲート**。スペックが`Combinator`以外の`lib/`内を2つの生の形式についてgrepし、ヒットがあれば失敗させる。これは安価だが既知のスペリングしか捕捉できないため、実際に拘束力を持つのは振る舞いゲートである。

**WD3 — メンバーディスパッチ**。

- `RbsDispatch#receiver_descriptor`（`rbs_dispatch.rb` ~L431）は`Interface`ファセットを`[name, :interface, type_args]`にマップする。
- `lookup_method`（~L517）はインターフェース定義から応答する。
- その後、オーバーロード選択、ブロックパラメータ束縛、および`self`置換がメンバーのメソッド型上で実行される。

**オーバーロード形状ルール**。ディスパッチは、メンバーのオーバーロードの1つが呼び出しの形状を受け付ける場合にのみ解決する。

- 呼び出しがブロックを渡す場合はブロックを受け付け、渡さない場合は必須ブロックがないこと。
- 位置引数の個数が、オーバーロードにrestパラメータがある場合を除き、必須＋省略可能の範囲内であること。
- 呼び出しが省略している必須キーワード引数がないこと。

それ以外の場合、呼び出しは`untyped`となる。引数ルールは`Dynamic`レシーバー上の呼び出しを一切チェックしないため、これ以外に形状の不一致を捕捉するものがない。このルールがなければ、ディスパッチはセレクタのフォールバックが選んだ任意のオーバーロードを採用し、そのオーバーロードの戻り値が次の呼び出しを誤らせてしまう。

**nilになり得るブロック渡しは両方の形状に一致する**。これは`expr`が非nilであると証明できない任意の値である場合の`&expr`を対象とする（#2815で修正: `top`または`Object`の値もnilになり得る）。実行時にはその呼び出しがブロックなしになる可能性があるため、以下の2つが成り立つ場合にのみ呼び出しが応答する。

- ブロックあり・ブロックなしの両方の形状が受け付けられること。
- 両者の戻り値が一致すること。

それ以外の場合、呼び出しは`untyped`となる。このルール以前は、nilになり得る`blk`を伴う`xs.each(&blk).with_index`がブロック付きオーバーロードの`Array[Integer]`を採用し、未定義の`with_index`を報告していた。`&:sym`は決してnilにならないため、通常のブロック形状を維持する。

**インターフェースが宣言していないメンバーは何も報告しない**。

- `untyped`レシーバー上の呼び出しと同様に、呼び出しは後続のティアへフォールスルーする。
- 値のクラスはインターフェースより広いため、`call.undefined-method`は偽陽性になる。`lib/rigor/plugin/base.rb`自体が、`_Environment`および`_Services`が宣言する範囲を超えて`class_ordering`および`io_boundary_for`を読み取っている。
- そのような呼び出しを報告するのは、#2686のオプトインルール`plugin.api-surface`の役割である。

**WD4 — スコープ: `Rigor::Plugin`のインターフェースのみ**。インターフェースの絶対名が`::Rigor::Plugin`名前空間にある場合、そのインターフェースはファセットを保持する。現時点では`sig/rigor/plugin/interfaces.rbs`内の5つのインターフェースが該当する。理由は以下のとおりである。

- #2686が必要とするのはこれだけである。
- ユーザーコードには一切到達せず、プラグインソースと`lib/`のみがそのような値を保持する。
- rbs coreの変換エイリアス（`int`、`string`、`path`、…）にはプラグインインターフェースが含まれないため、独自のルールを必要としない。

このスコープによりエイリアスメモの健全性も保たれる。

- インターフェースがファセットを保持するかどうかは、名前空間パスを通じた`TypeName`の純粋な関数である。したがって、どのファイルまたはワーカーが最初に変換しても、閉じたエイリアスは同じ型に変換される。
- そのため、展開結果をキーとしローダごとに保持される閉じたエイリアスメモ（`RbsLoader#closed_alias_translations`）は正しさを保つ。

  > [#2821](https://github.com/rigortype/rigor/pull/2821)による修正: 閉じた展開結果がローダを通じて展開されるネストしたエイリアスを保持し得るため、すべてのローダで共有される1つのメモが2つ目のローダに対して1つ目のローダの変換結果を返してしまっていた。

- 今後のスライスでファセットが型名以外の何かに依存するようになった場合、その入力をメモキーに追加しなければならない。それができない場合は、requirement変換と同様にメモをバイパスしなければならない。

**WD5 — どの出力がファセットを表示するか**。

| 出力 | 振る舞い |
| --- | --- |
| `sig-gen` | インターフェースディスパッチをオフにして解析するため、パリティ基準により出力はmasterと一致する。ディスパッチをオンにして計測したところ、1,358個のプラグインツリー候補のうち13個がスキップから新しい戻り値に変化し、そのうち11個は`_FactStore#publish`経由の`prepare: (untyped) -> nil`であった。ディスパッチをオフにすると、`lib`とプラグインツリーの両方がmasterと一致した。 |
| lens | `check`と同様にディスパッチを**オン**にして実行する。lensは`rigor check`が与える型として文書化されているため、`check`のスナップショットを共有し、個別のフィンガープリントを必要としない。`untyped`からある型に変化した15箇所のプラグインツリーの`body_return`サイトは意図した精度向上であり、12箇所が`_FactStore#publish`経由で`nil`を読み、3箇所が`Array`型を読んでいる。`lib`には変化がない。 |
| `type-of`、ホバー、`dump_type` | これらは`Dynamic[Rigor::Plugin::_Scope]`および宣言されたメンバー呼び出しの精密な結果を描画する。この描画は意図されたテキストである。 |

sig-genのみがディスパッチをオフにして実行する。sig-genはプラグイン作者がインターフェースに対して記述したわけではないRBSを書き出し、解析キャッシュも読まないため、キャッシュの同一性は関与しない。

**WD6 — スライス、ロールアウト、およびトリガー**。

| スライス | 内容 | デフォルト |
| --- | --- | --- |
| 1a | すべてのサイトでの`untyped?`述語、ユニオンマージ、両ゲート、およびパリティフィクスチャハーネス。`Interface`キャリアはまだ存在しないため、出力は構造上バイト単位で一致する | オン |
| 1b | `Rigor::Plugin`インターフェースキャリア、およびオーバーロード形状ルール・nilブロック渡しルールを伴うディスパッチ。各パリティサイトおよびプラグインインターフェース上のすべてのレビュー再現ケースに対するフィクスチャ。`structural-interfaces-and-object-shapes.md`内のスペックセクション「Interface-typed values」 | オン |
| 2 | ファセットを読み取る#2686（`plugin.api-surface`、ADR-128 WD6） | bleeding-edge |

トリガー:

- **再評価**。インターフェース値に起因する偽陽性はパリティバグである。修正は述語またはゲートを広げることで行い、サイトごとの例外は決して作らない。
- **撤回**。パリティの破損を述語で表現できない場合は消去に戻し、代わりに#2686にレシーバー構文検査を与える。例としては、ファセットのクラス名に基づく寛容さが挙げられる。

## 延期事項

**すべてのRBSインターフェースに対するファセット**。すべてのインターフェースにファセットを有効にした状態でコーパス全体の振る舞いパリティ差分がグリーンになった時点で再突入する。その段階で、rbs coreの変換エイリアスは計測によって決定する。最初のドラフトでは、それらを保持するとユニオンのクラスメンバーがすでにカバーしているファセットに対して診断テキスト（`got Dynamic[_ToInt] | Integer`）が変化することが判明した。

**構造的代入可能性（半分B）**。

- 内容: インターフェースのメンバーの1つで`call.undefined-method`が発火する場合に、インターフェースパラメータが値を拒否すること。
- プロトタイプで判明したこと: 3件の診断があり、すべて誤ったプロジェクトシグネチャに起因する偽陽性で、真陽性は0件であった。
- レビューで判明したこと: オラクルがundefined-methodチェーンの呼び出しサイトレキシカルアームを落としており、チェーン自体も#2792と#2793を見逃している。

以下の3つすべてが満たされたときに再突入する。

1. #2792および#2793が修正されること。
2. オラクルがレキシカルアーム（シングルトン`def`、ローカル変数上の`extend` / `define_singleton_method`、および`self.class`ミックスイン形式）を保持すること。
3. デリゲータを多用するコーパスで真陽性が示されること。

これに伴って移動する未解決の問い:

- ルートクラス（`Object`、`BasicObject`）の値は`maybe`と読むべきか？
- ユニオンの読み取りはevery-memberにすべきか？ 標準の読み取りでは`lib`上で20件のnullabilityおよび要素幅の偽陽性が追加された。
- ADR-64のname-onlyマルチオーバーロードチャネルをオラクル上に移すべきか？
- 両側で記述されたRBS用のシグネチャティアを設けるべきか？
- オラクルはどこに置くべきか？

**再利用されたRBSのロールテーブル**は半分Bとともに延期する。

- そのコンシューマーは半分B、ロール推論、および`hint.role-generalization.*`であり、いずれもまだ構築されていない。
- `conforms-to _Reader`はそれなしでもすでに`ConformanceChecker`を通じて解決している。

これら3つすべてのため、#929はオープンなまま維持する。

## 却下された代替案

| 代替案 | 理由 |
| --- | --- |
| **すべてのインターフェースに対するファセット（ドラフト2）** | すべてのプログラムのコア呼び出しおよびユーザーシグネチャに到達する一方、#2686はプラグインインターフェースのみを必要とする。これは却下ではなく延期であり、コーパス全体のパリティ差分がグリーンになった時点で再突入する。 |
| **消去のまま維持する** | コストも変更もゼロだが、#2686が開始できない。呼び出しを照合するインターフェースが存在しないためである。`Rigor::Plugin`にスコープを限定することで、ファセットはユーザーコードに到達せず、ゲートがパリティを保つ。 |
| #2686用のレシーバー構文検査（キャリアなし） | ローカル変数、ヘルパー、または`with_local`を通じた`scope`を追跡できない。これは撤回時のフォールバックである。 |
| パリティなしの`Dynamic[Interface]`（ドラフト1） | 正しいコードに対して7件の偽陽性を生じた。 |
| ユニオンマージと形状ルールなしのパリティ（ドラフト2） | 2件のジョインと`each.with_index`という3件のさらなる偽陽性を生じた。 |
| `Type::Interface < Type::Top` | 同一性比較を見逃し、`Combinator.dynamic`がそれを畳み込んでしまう。 |
| grepゲートのみ | 知らない形式をキーとする寛容さを見抜けない。振る舞いゲートなら見抜ける。 |
| 未宣言メンバーに対する`call.undefined-method` | 実行時にはそのメソッドが存在する。 |

## 結果

- **利点:**プラグインコードにおいて、プラグインインターフェースの宣言済みメンバーがその呼び出しを型付けする。`scope.type_of(node)`は`Rigor::Type::t`になり、`scope.environment`は`Dynamic[Rigor::Plugin::_Environment]`になる。#2686を開始できる。
- **利点:**パリティはコードリーディングの主張ではなく、振る舞いゲートによって維持される。
- **新たに到達可能:**サードパーティのプラグインコードにおける`call.possible-nil-receiver`。インターフェースがnilableとして宣言している`_Scope#local`、`_Scope#self_type`、`_Scope#source_path`、および`_Environment#nominal_for_name`の結果に適用される。この指摘は契約上正しく、ノミナルな`Rigor::Scope`レシーバーが与えるのと同じ指摘である。バンドルされたプラグインでは問題なく通過した。スライス1bはchangelog行を添えてデフォルトでオンにして出荷する。
- **欠点:**他の`untyped`値とのジョインのたびに、またADR-67 WD3がオーバーライドするあらゆる箇所で、ファセットが失われる。
- **欠点:** #929の大部分はオープンのままであり、一般的なファセットは独自の計測を待っている。
- **計測値:**
  - 第3ラウンドのHEAD時点で`lib`のアロケーションが+0.085%。ネストしたマージの前、ドラフト3のHEADでは`lib`で+0.007%、Mastodon `app`で+0.005%であった。
  - ドラフト2の0.45ポイントは`TypeName#to_s`によるものであり、ドラフト3ではこれを呼ばない。
  - ドラフト3の最初のユニオンマージは正規化のたびに配列を構築していたため1.26ポイントのコストがかかっていた。先にカウントすることでこれを除去した。

## 他のADRとの関係

- [ADR-1](../1-types/) — ケイパビリティロールと構造的インターフェース。本ADRはプラグインインターフェース値のみを扱う。
- [ADR-5](../5-robustness-principle/) — なぜ値が他のすべてのルールに対して`untyped`のままであるか。
- [ADR-64](../64-non-nil-argument-type-mismatch/) — name-onlyインターフェースチャネル。本ADRはこれを変更しない。
- [ADR-67](../67-parameter-type-inference/) — WD3のオーバーライド。インターフェースパラメータにも変更なく適用される。
- [ADR-84](../84-cross-file-return-memo-scoping/) — 述語がカバーするメモ化免除。
- [ADR-128](../128-plugin-hook-surface-interfaces/) — 本ADRが解決可能にするプラグインインターフェース。
  - WD5の継ぎ目は生じない。値は`untyped`であるため、`_Scope`は`scope: Scope`を通過する。
  - WD6のルールがファセットを読み取る。
