ステータス: **Accepted、2026-07-17——実装済み**。バックログはGitHub Issuesへ移る（項目ごとの判定を経て45件のissueを移行、トリアージ語彙＋`area:*`ラベルを作成、`v0.3.0` / `v1.0.0`のMilestoneを開設）。`docs/ROADMAP.md`は**削除**される。`docs/CURRENT_WORK.md`は全置換のセッションハンドオフになる（その日のうちに75,344 → 約4,100バイト、2回の書き直し）。`CHANGELOG.md`は変更なし。エンジニアリングスキルの構成はルートの`CONTEXT.md`用語集とともに`docs/agents/`のもとに着地する。`make docs-check`のもとで`spec/docs/agent_index_spec.rb`にゲートされる。

根拠: 両ファイルの同日の解剖（下記）と、[ADR-97](../97-adr-index-budgets/)の2つの基準——本ADRはそれをインデックスエントリーからフロー文書そのものへと拡張する。

## コンテキスト

3つの文書がプロジェクトの作業状態を運ぶと主張しており、そのそれぞれが宣言された意図からドリフトしていた。

- **`docs/ROADMAP.md`**（103,270バイト）は`MILESTONE.md`——TODOリスト、ユーザー向けのコミットメント面として意図されたことは一度もない——として生を始めた。2026-07-17までに、**そのセクション見出しの7つが自身をSHIPPED / COMPLETE / REMOVEDと宣言し**、「Released milestones（pointers only）」セクションは13 KBの再陳述されたCHANGELOGであり、そのリリース戦略の散文はそれに対して規範的なADR-50を再陳述していた。移行のために項目を判定したところ、ドリフトが見出しより深く走っていることが判明した。すなわち、オープンとして提示された項目——LRUキャッシュ退去、カバレッジ扱いやすさラベル、フォークベースの並列性、`ruby.wasm`プレイグラウンド——は数か月前に出荷されていた。
- **`docs/CURRENT_WORK.md`**は、その内容が数日で入れ替わる次セッションへのハンドオフであることを意図している。それは75 KBの追記専用ログになっており、しかも——より鋭い失敗——**最高優先度の位置に検証されていない主張**を運んでいた。すなわち、その2026-07-17の#1項目（「生きているバグ、まずこれをやれ」）は自身の再現手順（2026-05-01以来ガードされている）によって反証されており、「オープン」なAR-lambda項目は2026-05-28（`fde760a2`）以来修正されていた。
- **`CHANGELOG.md`**は、その役割がすでに正しかった唯一の面である。すなわち、ユーザーに影響する変更のユーザー向け要約であり、詳細はgitログである。それは変更を必要としなかった——これ自体が基準の証拠である。すなわち、それは3つのうち**保守された境界**（Keep a Changelog＋リリース準備の封印）を持つ唯一のものである。

## 作業上の決定

**作業項目はissueの形をしており、文書の形をしていない**。バックログのエントリーはステートマシン（open → triaged → in-progress → closed）、オーナー、ラベル、相互リンク、マージ時のクローズを必要とする。追跡されるMarkdownファイルはそのどれも持たないので、完了した項目は決して退去されない——それらは*蓄積*し、ファイルは丸ごと再判定されねばならないアーカイブへと朽ちる（この移行がその再判定であり、「オープン」項目の約40%はそうではなかった）。逆に**ハンドオフ**は文書の形をしている。すなわち、ちょうど1人の読者（次セッション）を持ち、「現在」以外の状態を持たず、自然な全置換のライフサイクルを持つ。

だから各面はその内容の形を得る。

### WD1 — GitHub Issuesがバックログ、Milestoneがリリース計画

すべての中期／長期の作業項目は、1つの`area:*`ラベルと1つのトリアージラベル（5つの正典的な役割——`needs-triage` / `needs-info` / `ready-for-agent` / `ready-for-human` / `wontfix`）を運ぶissueである。「次の切り出しが何を運ぶか」は、issueを`v0.3.0` / `v1.0.0`のMilestoneへ割り当てることで表現される。これはファイルの`MILESTONE.md`の遺産の直接の後継である。規約: [`docs/agents/issue-tracker.md`](../../agents/issue-tracker/)。外部PRはトリアージ面である（公開開発はPRをコード付きの機能要望にする）。

移行は**書き写されたのではなく判定された**。すなわち、4つの独立したパスが、ドラフト作成前に、すべてのROADMAP / CURRENT_WORK項目をコード、ADRのStatusブロック、git履歴に照らしてlive / shipped / staleに分類した。反対側から45件のissueが出てきて、出荷済みだが記載されていた項目は証拠とともに落とされた。

### WD2 — `CURRENT_WORK.md`はセッションハンドオフ、それ以外の何物でもない

それは1つの問い——*次のセッションは何をすべきか？*——に答え、作業がゴールラインを越えると丸ごと置き換えられる。2つのセッションより長生きするものは異なる住処を持つ。すなわち、バックログ → issue、運用上の落とし穴 → ワークフローのスキル、決定 → ADR、計測値 → `docs/notes/`、出荷済み → `CHANGELOG.md`。**主張を持ち越す前に検証せよ**——ファイルの2つの反証された項目は、ブックマークの中のADR-92の病（出荷されていない挙動を現在形で述べる）である。すなわち*検証されていない状態を現在のものとして主張する*こと。

### WD3 — `CHANGELOG.md`は変更なし

ユーザーに影響する変更のユーザー向け要約。詳細はgitログに住む。すでに正しい。三分割が完全であるためにここに記録されるのみである。

### WD4 — ゲート

ADR-97の基準2（機械的なゲートを持たない倹約ルールは一時的な状態である）に従い、`spec/docs/agent_index_spec.rb`は2つの軸を伸ばす。すなわち`docs/ROADMAP.md`が存在しないこと（その再作成が、本ADRが防ぐために存在する退行である）、そして`docs/CURRENT_WORK.md`が120行の上限内に留まること（それ以上を必要とするハンドオフは他人のコンテンツを運んでいる。今日のそれは62行）。

凍結された記録（ADR本文、`docs/notes/`、封印されたCHANGELOGセクション、コードの由来コメント）における解体前の「ROADMAP § …」の引用は、**歴史的引用**として残る——それらは、書かれた時点で項目がどこに住んでいたかを記述し、git履歴を通じて解決される。ライブなMarkdownリンクは、`make docs-check`のリンクゲートが緑を保つように、配線し直されるかリンク解除された。

## 影響

プラス:

- 各種類の知識はその寿命に鍵付けされたちょうど1つの住処を持ち、バックログはついにステートマシンを持つ——項目は丸ごとのファイル監査を待つのではなく、マージ時にクローズする。
- ハンドオフはセッション開始時に実際に読めるほど小さく、そのヘッダーは2つの反証を証拠として持つ、検証してから持ち越すというルールを運ぶ。
- エンジニアリングスキル（`/triage`、`to-issues`、`qa`、…）がここで使えるようになる。すなわち、その構成がスキャフォールドされ、ラベル語彙が存在する。
- 次の退行——再作成されたROADMAP、バックログを育てるハンドオフ——は失敗する`make docs-check`である。

マイナス:

- バックログはリポジトリを離れる。すなわちissueはgitでバージョン管理されず、ネットワークアクセスを必要とする。自己完結的なissue本文（それぞれが自身のリポジトリパスとゲートを引用する）によって、そしてどのみち`gh`が常設の依存であることによって緩和される。
- 45件のオープンなissueは、Markdownファイルが決して要求しなかったトリアージ衛生を課す。古びたissueはいまや可視の負債である。その可視性が要点だが、それは作業である。
- 凍結された記録における歴史的な「ROADMAP §」の引用はいまや削除されたファイルを参照する。受容される。すなわちそれらは過去の状態の引用であり、git履歴を通じて解決可能であり、凍結された記録を書き直すのは境界外である（ADR-92）。

## 他のADRとの関係

- **[ADR-97](../97-adr-index-budgets/)** —— 1週間違いの兄弟の決定。すなわちADR-97はインデックス*エントリー*が何を運んでよいかを直した。本ADRはフロー*文書*が何を運んでよいかを直す。両方とも同じ2つの基準（固定された仕事のための固定された予算、指示に対するゲート）に立ち、同じspecファイルを共有し、本ADRは`AGENTS.md`の常設ポリシー前提リストでそれに加わる。
- **[ADR-50](../50-release-engineering-and-stability-strategy/)** —— リリース戦略を規範的に所有する。ROADMAPの戦略散文は再陳述だった。Milestoneはその切り出しを運用化する。その中の何も変わらない。
- **[ADR-92](../92-normative-status-fidelity/)** —— 検証してから持ち越すというルールは、その宣言するかマークするかの規律をハンドオフに適用したものである。すなわち沈黙（検証されていない持ち越された主張）は決して正直な状態ではない。
