ステータス: **Proposed、2026-08-15**。何も実装されていない。`rigor unused`のスライス群が依拠する決定を固定する（[#344](https://github.com/rigortype/rigor/issues/344)がアンブレラ;[#347](https://github.com/rigortype/rigor/issues/347)がトレーサーバレット）。8つの作業上の決定はすべて確定済み——WD5とWD8は1回の改訂のあいだ未決のまま持ち越され、2026-08-15にクローズした。

根拠: [`docs/notes/20260813-unused-constant-fp-baseline.md`](../../notes/20260813-unused-constant-fp-baseline/)（3プロジェクトのコーパス計測、redmineは全件裁定済み）と、RigorがShopifyのrubydexから何を消費し、何にはならないかをすでに確定した[ADR-21](../21-rubydex-evaluation/)。

## コンテキスト

「ここのどのコードが死んでいるか？」は、あらゆる大規模Rubyコードベースが問う問いであり、Rigorはそれに答えるのに際立って適した位置にいる: Rigorはすでに定数を名前マッチではなくRubyのネスト規則を通じて解決しており、それこそが本物の答えを`grep`から分かつ能力だ。きっかけは、rubydexを使って未使用のRailsコントローラーを見つけたという2026年のレポートで、その候補リストは3回の訂正を経て`631 → 9 → 3 → 2`と減衰し、その著者はこのツールは答えを出すのではなく候補を絞り込むものだと結論づけていた。

我々はその結論を継承するのではなく、同じファネルを自分たちで計測した。redmineでは、次第に高価になるルート知識の4段階を経たあと、**57件の候補が生き残り、うち4件が本物——精度7.0%**であり、57件すべてを手で裁定した。Mastodonとconference-appは同じファネルでそれぞれ113件と14件の生存者を出した。

このADRが仕える意図: 「どのコードが死んでいるか？」を答えられない問いから、**人間が処理していけるレビューキュー**へと変えること。それを、`rigor check`を走らせる価値の源である偽陽性の予算を一切使わずに行うこと。この2つの目標は真っ向から緊張しており、以下のあらゆる決定は、それを同じ方向で解消した帰結である。

## 決定

弁別基準を一度だけ述べる。すべての作業上の決定はここから導かれるからだ:

> **その精度が、どれだけうまく解析するかではなく、アナライザーが持ちえない知識によって上限づけられるシグナルは、診断ストリームではなくレポートに属する**。

到達可能性はまさにそのように上限づけられている。その正確さは*ルート集合*の関数だ: ルート（route）・DIの配線・リフレクション・フレームワークの命名規約・解析ルートの外側の呼び出し元。推論を改善してもそれは動かない。対照的に`call.undefined-method`は、その精度*が*解析品質の関数だ——ディスパッチャーを改善すればそれも改善する。これがその境界線であり、再利用可能だ: 将来のシグナル（「おそらく到達不能な分岐」レポート、「使われていない可能性の高い設定キー」）を、この決定を蒸し返さずに判定する。

### WD1 — レポートであって診断ではない、いかなる重大度であっても

`rigor unused`は`rigor triage` / `rigor coverage`ファミリーの独立したサブコマンドである。`check`の診断ストリームへは、`:info`としてであってもMUST NOT出力してはならない。精度7.0%では、診断は人々にツールを迂回することを教え、それは機能が返すものより高くつく（AGENTS.md § Implementation Guidelines;[ADR-5](../5-robustness-principle/)）。

### WD2 — 参照カウントではなく、ルートからの到達可能性

モデルは、明示的なルート集合からのマークアンドスイープである。2つの計測されたファクトがこれを強いる:

- **ルート知識がレバーのすべてである**。ルート（route）由来のルートを差し引くと、3つのターゲットでクラス層の40% / 62% / 67%が取り除かれた——他のあらゆる段階を合わせたよりも多く、しかもそれは正規表現の抽出器でのことだ。
- **解析ルートを広げることはレバーではない**。宣言と参照は同じ「解析対象ファイル」述語でゲートされているので、両者は一緒に広がって相殺する: +1 / −3 / +2件の候補。Rigorは「`config/`を加えればレポートが改善する」と述べる助言をMUST NOT出荷してはならない。

### WD3 — ルートはプラグインが供給する

コアはルートの*プロトコル*を定義する;フレームワークの知識はプラグインに留まり、既存の`produces:` / `fact_store`機構で運ばれる（[ADR-9](../9-cross-plugin-api/)・[ADR-2](../2-extension-api/)）。`rigor-rails-routes`はすでにRailsランタイムなしにPrism経由で`config/routes.rb`を解釈しており、これは元記事のアプローチを2つの軸で上回る: ブートしないこと、そして`get "..." if <cond>`というルート（route）の両分岐が見えること——元記事が手作業で行わねばならなかったステップだ。

2つの規約ルールがredmineの残る作為の66%を引退させる（ヘルパーモジュールの対応付けと、「本体が登録DSLを呼ぶクラスはルートである」）。どちらもプラグインの形をしており、それが要点だ。

### WD4 — `cannot-decide`は出力契約の一部

Rigorが未参照であると*証明*できない定数はMUST判定不能として報告されなければならず、決して「unused」に畳み込んではならない。動的な構築（`constantize`・`const_get`・補間された名前）、YAML / ロケール内のデータとしてのクラス名、ERBテンプレートはすべて降格させる。[ADR-65](../65-diagnostic-evidence-tier-and-doc-url/)のエビデンスティアで階層化し、読み手が平坦なリストを読むのではなく確信度でソートできるようにする。

### WD5 — プロジェクト全体のみ;`--incremental`は吸収せず拒否する

到達可能性の答えはフル実行の上でのみ健全であり、これは[ADR-45](../45-unchanged-project-fast-path/)の実行結果キャッシュおよび[ADR-46](../46-incremental-dependency-graph/)のファイルごとのインクリメンタルパスと衝突する。

`rigor unused`は`--incremental`を、黙ってフルパスを強制するのではなく、説明メッセージと非ゼロ終了でMUST拒否しなければならない。却下された選択肢は実コストを隠す——高速パスを求めたユーザーが何のシグナルもなく低速パスを得る——うえ、誰かが後にそれを最適化で消し去ろうとするまさにその場所で、健全性の境界を見えなくする。拒否は自己文書化される。この挙動はMUSTspecで固定されなければならない: これを間違えたときの失敗モードはエラーではなく、自信満々に間違った候補リストだからだ。

### WD6 — 立ち上げ時はクラスとモジュールの定数のみ

値定数の層は対象外のままとする。`Scope#in_source_constants`は設計上ファイルごとであり、クロスファイルのプロジェクトシードには運ばれないので、別ファイルから読まれる値定数は決して解決されず、その候補性は構成上偽である——コーパス全体で38 / 89 / 0件の候補が、正しくなりようのないものだ。これを再開するのは[#352](https://github.com/rigortype/rigor/issues/352)であり、それ自身の偽陽性のサーフェスを伴う。

所有権とは、ここで宣言されていることではなく**ここで最初に宣言されている**ことを意味する: gemや標準ライブラリのクラスを再オープンすると、現状ではそれがプロジェクトの宣言として登録され、それが1つのイニシャライザからredmineの作為3件を生んだ。

### WD7 — 参照コーパスは解析コーパスより広い

`PathExpansion::RUBY_GLOB`は`**/*.rb`なので、`.rake`ファイルは`paths:`の内側にありながら決して読まれない——3ターゲットのうち2つで純粋な作為だった。参照を収穫するためにファイルを読むのは型チェックするよりはるかに安価であり、レポートはMUSTより広いコーパスを取らなければならない。

### WD8 — 参照はその参照元のロールを運ぶ

自分自身のspecからのみ参照されるクラスは、生きたテストを持つ死んだ本番コードだ。テスト参照を到達可能性として数えるとその発見が隠れる;無視するとノイズを製造する。どちらも正しくない。2つは厳しい答えと緩い答えではなく、異なる答えだからだ。

したがって参照グラフのエッジは**それが由来するファイルのロール**（production / test / task / config）をMUST運ばなければならず、`used only by its own test`はバケットの境界ではなくMUST報告されるカテゴリーでなければならない。これはフィルタではなくデータモデルの決定だ: ロールはエッジが記録されるときに記録されなければならず、#349の後から後付けすることはできない。

### 再評価のトリガー

WD1は、コーパスターゲットでの裁定済み精度が約80%——診断がノイズであることをやめるに足る高さ——を超えたときに再開し、それより前には再開しない;より低い基準は算術を変えずに議論を蒸し返すだけだ。WD3は、あるルートのクラスが本当にフレームワーク非依存（プロジェクト全体の設定規約）だと判明したときに再開する。それはプラグインではなくコアに属するだろう。WD6は#352が着地した瞬間に再開する。WD7は、より広い参照コーパスが計測可能に実行を遅くしたときに再開する。ノートのコスト論はそうならないと予測している。WD2・WD4・WD5は構造的であり、再設計以外のトリガーを持たない。

## 却下・先送りされた代替案

| 代替案 | 却下理由 |
| --- | --- |
| `:info`診断として出荷する | それでも読み手に出力を無視することを訓練するし、`:info`は人々が最初にフィルタする重大度だ。この基準は重大度による逃げ道を認めない。 |
| 参照カウント（「参照ゼロ ⇒ unused」） | 素朴な形はRigor自身の`lib`で99.7%のFPを計測した;元記事のあらゆる訂正は欠けていた参照ではなく欠けていたルートだった。 |
| 緩和策として`paths:`を広げる | 計測済み: +1 / −3 / +2。宣言は参照とともに広がる。 |
| Railsの知識をコアにハードコードする | ADR-2のプラグイン境界に矛盾する;収量最大の2つのルールはフレームワークの規約であり、それこそプラグインの存在理由だ。 |
| rubydexのクロスリファレンスインデックスを消費する | ADR-21のTrack 3がすでにこれをLSPロードマップに条件づけている;Rigorが必要とする宣言の基板はすでに存在する。 |
| 立ち上げ時に値定数を含める | #352が着地するまでは構成上偽である。 |
| 未使用*メソッド* | [#351](https://github.com/rigortype/rigor/issues/351)へ先送り。型を持たないインデクサーには届かないところへRigorは届きうるが、その層はこの層の問題を10倍の量で継承し、まずAPI境界の定義を必要とする。 |

## 帰結

**良い点**。この問いが、診断ストリームの信頼性に触れずに擁護可能な答えを得る。ルートのプロトコルは将来のあらゆる到達可能性の問いに再利用できる。静的なルート（route）パースは、元記事が自動化できなかった手作業のステップを取り除く。

**悪い点**。精度7%のレポートはレビューキューであり、ドキュメントは欠陥の数を示唆するのではなくそのことを率直に述べなければならない——過剰に売り込まれたレポートは、ユーザーがそれを開かなくなる失敗モードだ。ルートの供給には非対称性も伴う: *過剰*に供給するルートのソースは本物のデッドコードを黙って隠し、それは供給不足のものより悪いので、各プラグインの寄与にはそれ自身のコーパスチェックが必要だ。

**持ち越し**。 #345のプローブ計装は#349の再計測が終わるまで4つのエンジンファイルに残り、その後取り除かれる（#344で追跡）。

## 他のADRとの関係

[ADR-21](../21-rubydex-evaluation/)はrubydexの問いを3つのトラックで確定した;これはRigorがネイティブに何を構築するかという独立した4番目の問いであり、それを再開しない。[ADR-45](../45-unchanged-project-fast-path/) / [ADR-46](../46-incremental-dependency-graph/)は、WD5が突き合わせて解決しなければならないキャッシュ境界を所有する。[ADR-9](../9-cross-plugin-api/)と[ADR-2](../2-extension-api/)はルート寄与の機構を供給する。[ADR-65](../65-diagnostic-evidence-tier-and-doc-url/)はティアの語彙を供給する。[ADR-5](../5-robustness-principle/)はWD1が強制する規律である。
